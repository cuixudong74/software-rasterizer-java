# software-rasterizer-java

纯进程内软件光栅化与裁剪管线：输入带变换的三角网格与相机参数，输出确定性位图。
不依赖图形设备与外部服务，所有结论与异常均可在本地复现
（`mvn test`，45 个自动化测试）。

管线阶段：

```
model/view 变换 -> 视空间近裁剪面裁剪 -> 投影 -> 裁剪空间视锥裁剪
-> 透视除法 -> 视口映射 -> 分块并行光栅化 -> 成功时一次性提交位图
```

## 坐标与深度约定

- **模型/世界/视空间**：右手系。相机位于 `eye`，看向 `target`，视空间下相机
  朝 **-Z** 方向看（可见点满足 `z_view <= -near`）。
- **矩阵**：行主序 4x4，列向量约定 `v' = M * v`。组合顺序
  `clip = projection * view * model * position`。
- **裁剪空间/NDC**：OpenGL 约定，可见区域 `-w <= x,y,z <= w`，
  NDC 三轴均在 `[-1, 1]`，近裁剪面映射到 `z_ndc = -1`，远裁剪面为 `+1`。
- **视口映射**：`sx = (x_ndc + 1) * 0.5 * width`，
  `sy = (1 - (y_ndc + 1) * 0.5) * height`（+Y 向上，屏幕 y 向下）。
  像素在中心 `(x + 0.5, y + 0.5)` 处采样。
- **深度**：深度缓冲存储 NDC z（`[-1,1]`），它在屏幕空间是线性的，
  因此线性插值本身就是透视正确的。深度测试为 **LESS**（更小者更近），
  清屏值为 `1.0`（远平面）。每次 `render` 调用先清屏
  （颜色 `0xFF000000`，深度 `1.0`）。
- **正面判定**：屏幕空间有向面积 **为正** 的三角形为正面
  （对应世界空间中从相机看逆时针）。开启背面剔除时，面积 `<= 0`
  的三角形被丢弃。

## 填充规则（top-left 规则）

三角形覆盖判定是确定的：像素中心严格位于所有边内部，或恰好落在
**top-left 边** 上时，像素被覆盖。将环绕方向规范化为内部在边函数正侧后，
边 `A->B` 是 top-left 边当且仅当
`(B.y - A.y > 0) || (B.y == A.y && B.x - A.x < 0)`（屏幕 y 向下）。

推论：相邻三角形的共享边被且仅被其中一个三角形光栅化——
**不漏填、不重复覆盖**（由 `FillRuleTest` 验证）。零面积退化三角形被跳过。

## 裁剪

- **视空间近裁剪**：投影前先在视空间对 `z <= -near` 做
  Sutherland-Hodgman 裁剪，保证所有存活顶点投影后 `w > 0`，
  避免 `w < 0` 时裁剪空间不等式翻转的经典陷阱。
- **裁剪空间视锥裁剪**：对其余 5 个平面（`±x`、`±y`、`z <= w`）裁剪；
  近面 `z >= -w` 已由视空间裁剪蕴含，跳过以避免双重裁剪的浮点噪声。
- 跨越裁剪面的三角形被切分为凸多边形并扇形三角化；边界顶点的颜色与
  纹理坐标在裁剪空间线性插值（透视除法在裁剪之后，故该插值是精确的）。
- 裁剪一致性由 `ClipPipelineTest` 验证：自动裁剪结果与手工裁剪几何
  逐像素一致；完全在近面后/视锥外的三角形被整体丢弃。

## 属性插值与纹理

- 颜色与纹理坐标按 **透视正确** 方式插值：屏幕空间线性插值
  `attr/w` 与 `1/w`，再相除还原。
- 纹理采样为最近邻；越界寻址行为由 `Texture.WrapMode` 显式定义：
  - `CLAMP`：钳制到边缘纹素；
  - `REPEAT`：小数回绕（`u - floor(u)`）。
  非有限坐标（NaN/Inf）定义为采样 `(0,0)` 角纹素，不存在未定义行为。
- 有纹理时最终颜色 = 纹素 RGB 与顶点颜色逐通道调制；无纹理时直接使用
  顶点颜色。颜色通道钳制到 `[0,1]`。

## 并行与确定性

- 帧缓冲按 `tileSize` 切分为互不相交的像素块，三角形按包围盒分箱到块，
  每块内严格按提交顺序光栅化，由固定大小线程池并行处理。
- 每个像素只会被一个块写入，因此 **任意 `tileSize`/`threads` 组合的输出
  逐像素一致**（`ParallelConsistencyTest` 对多组配置断言位图完全相同）。
- 渲染先写入私有临时目标，**成功后才整体拷贝** 到调用方的帧缓冲；
  异常、中断或超时不会留下半成品位图，线程池必然被关闭
  （`shutdownNow`），不泄漏资源。

## 配置项（`RenderConfig`）

| 字段 | 含义 | 约束 |
|---|---|---|
| `tileSize` | 并行像素块边长 | `> 0` |
| `threads` | 光栅化工作线程数 | `>= 1` |
| `backfaceCulling` | 是否背面剔除 | - |
| `depthTest` | 是否启用 LESS 深度测试 | - |
| `timeoutMillis` | 单次渲染墙钟超时；`0` 表示不限 | `>= 0` |

`RenderConfig.defaults()`：`tileSize=32`，`threads=可用核数`，剔除与深度测试开启，无超时。

## 非法输入诊断

所有非法输入抛出 `RenderException` 并带有**可区分的诊断信息**，
非法数值不会悄悄传播到输出：

- 顶点位置/颜色/UV 含 NaN 或 Inf（指明是第几个顶点的哪个分量）；
- 索引越界、索引数不是 3 的倍数、空指针组件；
- 相机参数非法（`fovY` 不在 `(0,π)`、`aspect <= 0`、`near/far` 不满足
  `0 < near < far`、视线与 up 平行、eye 与 target 重合）；
- 模型矩阵或变换中间结果出现非有限值；
- 帧缓冲尺寸非正或超过内存上限（1 亿像素）；
- 渲染超时（`render timed out after N ms`）或被中断。

失败时调用方的帧缓冲保持原样（见 `InvalidInputTest`）。

## 大规模场景稳定性

- 超大三角形（坐标 ±1e12）、极细三角形、远超屏幕范围的三角形均被稳妥
  处理：包围盒被钳制到屏幕，耗时与屏幕面积而非三角形尺寸相关。
- 内存上限：帧缓冲像素数硬上限 1 亿；纹理与网格按输入规模线性占用。
- 2 万三角形场景在 CI 下秒级完成（`StabilityTest`）。

## 使用示例

```java
Framebuffer fb = new Framebuffer(640, 480);
Renderer renderer = new Renderer(RenderConfig.defaults());
Camera camera = new Camera(
        new Vec3f(0, 0, 3), new Vec3f(0, 0, 0), new Vec3f(0, 1, 0),
        Math.PI / 3, 640.0 / 480.0, 0.1, 100.0);
renderer.render(fb, mesh, Mat4f.rotationY(0.5), camera, texture);
BufferedImage image = fb.toImage();   // 或读取 fb.colorBuffer()
```
